# Requirements

We have a web server container running the nginx image. The access and error logs generated by the web server are not critical enough to be placed on a persistent volume. However, Nautilus developers need access to the last 24 hours of logs so that they can trace issues and bugs. Therefore, we need to ship the access and error logs for the web server to a log-aggregation service. Following the separation of concerns principle, we implement the Sidecar pattern by deploying a second container that ships the error and access logs from nginx. Nginx does one thing, and it does it well - serving web pages. The second container also specializes in its task - shipping logs. Since containers are running on the same Pod, we can use a shared emptyDir volume to read and write logs.

Create a pod named webserver.

Create an emptyDir volume named shared-logs.

Create a regular container in the webserver pod from the nginx:latest image named nginx-container, and a sidecar container from the ubuntu:latest image named sidecar-container. You can create sidecar-container as a native sidecar (an init container with restartPolicy: Always) or as a second regular container under spec.containers; both are accepted.

Add the following command to the sidecar-container "sh","-c","while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done"

Mount the shared-logs volume in both containers at /var/log/nginx. Create the pod in the default namespace and ensure both containers are in a running state.

Note: The kubectl utility on the jump-host has been configured to work with the Kubernetes cluster.

---

## 1. Pod Manifest (`webserver.yaml`)

Save the following configuration as `webserver.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: webserver
  namespace: default
spec:
  volumes:
    - name: shared-logs
      emptyDir: {}
  containers:
    - name: nginx-container
      image: nginx:latest
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
    - name: sidecar-container
      image: ubuntu:latest
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
      command:
        [
          "sh",
          "-c",
          "while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done",
        ]
```

---

## 2. Deployment & Verification Steps

### Step 1: Apply the Manifest

Deploy the Pod to the `default` namespace:

```bash
kubectl apply -f webserver.yaml
```

**Expected Output:**
```text
pod/webserver configured
```

### Step 2: Verify Pod & Container Status

Confirm that both containers (`2/2`) inside the Pod are running without restarts:

```bash
kubectl get po
```

**Expected Output:**
```text
NAME        READY   STATUS    RESTARTS   AGE
webserver   2/2     Running   0          3m26s
```

### Step 3: Inspect the Shared Volume Inside `nginx-container`

Open an interactive shell inside `nginx-container` to check the mounted `/var/log/nginx/` directory:

```bash
kubectl exec -it webserver -c nginx-container -- /bin/bash
```

Inside the container:
```bash
cd /var/log/nginx/
ls
exit
```

> **Note:** The `/var/log/nginx/` directory will initially appear empty because mounting an `emptyDir` volume overrides the default log symlinks included in the official `nginx:latest` image.

### Step 4: View Sidecar Container Logs

Check the output of `sidecar-container` to confirm the log-reading loop is running:

```bash
kubectl logs webserver -c sidecar-container -n default
```
